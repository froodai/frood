# M9. Первый час — предложение

> Статус: принято (раунд 23, 25.10): F1, F2, F4, F5 — да; QF1 — (а), QF2 — (а), QF3 — (б); F3 — переделан по замечанию «не надо пачку шаблонов» (§3).
> Основание: план «После MVP» ([25](25_hub_ux_plan.md) §2, порядок M8 → M9 → M10 принят в раунде 21), исследование «Frood как хаб» (H1–H4, H6, HC2), что уже сделано ([18](18_implementation_log.md)).

## 0. Зачем

Сейчас первый час с Frood уходит на `frood.yaml`. Нужно вписать вход через Google, ключи, Telegram и бэкапы, потом собрать строки подключения для Claude Code. Польза при этом видна только через неделю, когда память накопится.

Цель M9 — за первый час человек:
1. ставит Frood на свой ноутбук одной командой и отвечает на несколько вопросов;
2. подключает Claude Code или Codex готовой строкой;
3. забирает то, что о нём уже помнят его ассистенты;
4. видит в «Сейчас» свою память, а в Inbox — только то, где эти памяти расходятся.

## 1. F1. Ноутбук — путь по умолчанию (H3)

Сейчас ноутбук работает, но описан как частный случай. Шаблон рассчитан на сервер: вход через Google, публичный адрес.

**Предлагаю.** Установка по умолчанию — на ноутбук:
- Frood в Docker Desktop, порт только на 127.0.0.1, без домена и без провайдера входа.
- **Вход в консоль — «на этом компьютере».** Без пароля и только для адресов из `auth.allow`. Работает, только пока у установки нет публичного адреса. Сейчас так устроен вход `dev`; он станет обычным, с понятным названием.
- **Claude Code, Codex, Cursor** подключаются к `http://127.0.0.1:8080/mcp` с личным токеном. Мастер печатает готовые команды.
- **Telegram** работает и с ноутбука: бот сам опрашивает Telegram. Ночные джобы догоняют пропущенное после сна.
- **Чего не будет на ноутбуке:** Claude в браузере и ChatGPT нужен публичный HTTPS-адрес. Это сервер или туннель (M10).
- **Переезд на сервер** — уже есть: бэкап и `frood restore`.

**QF1.** Вход в консоль на ноутбуке:
- (а) «на этом компьютере», без пароля, только с этой машины и только для адресов из `auth.allow`;
- (б) как сейчас на сервере — только через Google или другой OIDC.

Я предлагаю (а): ноутбук и так защищён входом в систему, а Google Cloud Console — самый неприятный шаг установки.

## 2. F2. Мастер `frood init` (H1)

Сейчас `frood init` пишет шаблон с хранилищем и пустым входом, остальное — руками.

**Предлагаю.** Запущенный в терминале `frood init` задаёт вопросы. У каждого есть ответ по умолчанию, Enter его принимает.

| Вопрос | По умолчанию | Что пишет |
|---|---|---|
| Где работает Frood: ноутбук, домашний сервер, сервер с доменом | ноутбук | `server`, `deploy`; для домена — `public_url` и Caddy |
| Ваш адрес почты | из `git config user.email` | `auth.allow`; вход «на этом компьютере» или Google для сервера |
| Чем читать заметки: ключ Anthropic, ключ OpenAI, позже | — | аккаунт, модель извлечения (самая дешёвая из подходящих), включённое извлечение |
| Telegram: токен бота от @BotFather или позже | позже | модуль Telegram |
| Голосовые: тем же ключом OpenAI или позже | если есть ключ OpenAI — да | модуль распознавания |
| Бэкапы: папка (например, внешний диск) и по желанию S3/B2 | папка `~/frood-backups` | модуль бэкапа, ключ восстановления, расписания |
| Утренняя сводка: время и часовой пояс | будни 08:30, пояс системы | расписание сводки, напоминания о сроках |

После вопросов мастер:
1. пишет `frood.yaml` и файл секретов;
2. запускает `frood apply`;
3. проверяет каждое подключение без трат: ключ — списком моделей, бота — `getMe`, бэкап — пробной записью;
4. печатает адрес консоли, команды для Claude Code и Codex с личным токеном и код `/link` для бота.

Флаг `--yes` берёт ответы по умолчанию без вопросов (для скриптов и CI), прежние флаги остаются.

## 3. F3. Стандартный набор (H2)

Стандартные джобы уже встроены в сервер: извлечение, распознавание, индекс, ночной проход, «сначала исследовать», сводка, бэкап. Но расписание сводки и напоминаний пустое, пока его не впишут.

**Принято по замечанию (раунд 23): никаких шаблонов.** Разумные значения встроены в сервер, а не вписываются в `frood.yaml` пачкой:
- сводка по будням утром в часовом поясе человека;
- напоминания о сроках — за день и в день срока, в 09:00;
- бэкап каждые 6 часов и проверка восстановления раз в неделю, если бэкап настроен.

Всё это меняется в консоли («Автоматизации») или в `frood.yaml`. Мастер спрашивает только время сводки. Ночной проход включается, когда подключён источник и есть агент.

`bundles/standard` убирается; галерея рецептов (H15) не планируется.

## 4. F4. Свои правки без ревью (H6)

Сейчас правило `own-facts` принимает сразу только новое знание человека. Например, при записанном «мы на Postgres 16» заметка «перешли на Postgres 17» ждёт решения.

**Предлагаю.** Изменение знания, записанного самим человеком, принимается сразу. Условия:
- изменение пишет этот же человек (его заметка, его импорт, его правка в консоли);
- у знания нет свидетельств из чужих источников: другого человека, агента, подключённого источника;
- изменение ни с чем не спорит.

Старая версия остаётся в истории, «Что изменилось» показывает замену, отменить можно одной кнопкой. Если знание пришло из YouTrack или от коллеги, изменение ждёт решения, как сейчас.

## 5. F5. Импорт накопленной памяти (H4)

У Claude Code, Codex, OpenClaw и Hermes память лежит файлами на диске. У ChatGPT и Claude её не выгрузить: нет ни API, ни кнопки, зато сам ассистент помнит и умеет вызывать инструменты Frood.

**Предлагаю.**
- **`frood import`** запускается на машине, где лежат файлы, и работает и с сервером: `--server`, `--token`.
  - Находит память: Claude Code (`~/.claude/projects/*/memory/`), Codex (`~/.codex/memories/`), OpenClaw (`MEMORY.md`, `USER.md`, memory-wiki), Hermes, любую папку Markdown (`--folder`).
  - Показывает найденное с примерной ценой извлечения и спрашивает одно подтверждение. Пример: «Claude Code — 9 проектов, 41 файл; Codex — 1 файл; ≈ 120 тыс. токенов, около $0.15 на самой дешёвой модели».
  - Отправляет каждый файл источником с пометкой, откуда он: «память Claude Code, проект frood».
- **Текст файлов читается.** Сейчас загруженные `.md` и `.txt` извлечение пропускает. Будет читать их текст, и для импорта, и для заметок с файлом.
- **В Claude и ChatGPT** у Frood появится MCP-подсказка «Перенести память во Frood». Ассистент перечисляет всё, что помнит о человеке, и записывает это заметками. В Claude Code она становится командой `/mcp__frood__import_memory`. Писать через MCP в ChatGPT могут Business и Enterprise.
- **Историю чатов** из ZIP-выгрузок не берём: тысячи разговоров через модель стоят дорого, а память ассистентов уже их выжимка.
- **Что попадает в Inbox.** Импорт — память самого человека, поэтому принимается сразу по правилам `own-facts` и §4. В Inbox идёт только то, где памяти расходятся: «Claude Code помнит Postgres 16, Codex — 17». Первый разбор показывает эти расхождения одним списком.

**QF2.** Знания из памяти ассистентов:
- (а) принимаются сразу с пометкой «из памяти ассистента · не проверено»; пометка видна в ответах и консоли и снимается одним нажатием «Верно» или при любом подтверждении;
- (б) принимаются сразу без пометки, как свои заметки;
- (в) все ждут решения в Inbox.

Я предлагаю (а): это пересказ модели, часто устаревший. Пометка честно это говорит и не заставляет разбирать сотни пунктов.

## 6. Находки агентов из обычных источников (HC2)

Сейчас всё, что агент нашёл в обычном (не доверенном) источнике, ждёт человека. Ночной проход по YouTrack приносит десятки новых знаний за ночь — Inbox превращается в поток.

**QF3.** Находки агентов из обычных источников:
- (а) как сейчас — всё ждёт решения;
- (б) новое знание принимается сразу с пометкой «не проверено» (флаг `needs_verification` в модели уже есть). Ждут решения изменения сроков, ответственных и решений, а также конфликты и слияния. Пометка видна в ответах ассистентов («по данным YouTrack, не проверено») и снимается одним нажатием.

Я предлагаю (б). Требование 01 §4 — «автоматически принимается не всё» — выполняется: изменения важного и конфликты по-прежнему за человеком. Цена: в памяти будут непроверенные факты, но с пометкой, источником и историей.

## 7. Порядок и выпуски

1. Ноутбук по умолчанию и стандартный набор (§1, §3) — вместе с мастером (§2).
2. Свои правки без ревью (§4) и решение по QF3 (§6).
3. Импорт: чтение текста файлов, `frood import`, MCP-подсказка (§5).

Каждый шаг — свой выпуск. Проверка:
- в CI — `frood init --yes` на чистой машине доходит до работающей установки, импорт папки Markdown даёт знания и одно расхождение в Inbox;
- вручную — на ноутбуке с настоящими Claude Code и Codex.

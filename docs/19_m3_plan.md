# M3. Ввод и извлечение — план реализации

> Этап M3 из [17_mvp_plan.md](17_mvp_plan.md): `/v1/capture`, Telegram (ввод), облачное распознавание, `extract` с поиском похожих, связывание сущностей, поиск. Результат — шаги 1–2 сценария: голосовое в Telegram становится утверждением, и его находит Claude.
> Основание: фаза 3 (события, джобы как вызов возможностей), фаза 4 (ввод, извлечение), фаза 6 (модули, протокол модулей), R1′ (чьё это действие).

## 1. Поток

```
Telegram-модуль ─┐                       ┌─▶ transcribe (media.transcribe, модуль stt-openai) ─┐
iOS Shortcut ────┼─▶ POST /v1/capture ─▶ Source + source.captured ─▶ dispatcher ─┤                                                      ├─▶ extract (llm.complete) ─▶ Proposals ─▶ политика
MCP capture_note ┘                       └────────────────────────────── (текст) ─────────────┘
                                                                     assertion.created ─▶ embed (эмбеддинги) ─▶ поиск
```

## 2. Что строим

| Часть | Где | Что |
|---|---|---|
| Захват | `frood-api`, миграция 0004 | `POST /v1/capture`: JSON (текст) или multipart (файл: голос, аудио, документ). Файлы — в таблице `blobs` (до 25 МБ). Ответ сразу: `source_id`, статус обработки. `GET /v1/sources/{id}` показывает статус и созданные предложения |
| Dispatcher и очередь | новый крейт `frood-dispatch` | Читает журнал со своим checkpoint, применяет правила `on:` джоб, ставит запуски в очередь (идемпотентно: джоба + событие), исполняет с повторами и растущей задержкой. Таблицы `runs`, `dispatcher_checkpoints` |
| Джобы | `frood-dispatch` | `transcribe` (аудио → текст как новая версия источника), `extract` (текст → наблюдения → сущности → похожие утверждения → предложения), `embed` (эмбеддинги новых версий утверждений). Определения по умолчанию встроены; в `frood.yaml` (`jobs:`) их можно переопределить или выключить |
| LLM gateway | новый крейт `frood-llm` (builtin-модуль) | `llm.complete@1` и `llm.embed@1` через API Anthropic и OpenAI; аккаунты — секция `accounts:` |
| Хост модулей | новый крейт `frood-modhost` | Контейнерные модули из секции `modules:`: `apply` добавляет их в Compose, ядро читает манифест, проверяет здоровье, маршрутизирует вызовы возможностей, выдаёт сервисный токен со scopes из манифеста |
| Распознавание | `modules/stt-openai` (Apache-2.0) | `media.transcribe@1` через OpenAI |
| Telegram | `modules/telegram` (Apache-2.0) | Long polling (публичный адрес не нужен); `/link <код>` связывает аккаунт; текст, голос и файлы → `/v1/capture` от имени связанного пользователя; ответ «сохранено», затем итог обработки |
| Связка каналов | `frood-api`, `frood-cli` | `frood link telegram --email …` и `POST /v1/channels/links` выдают одноразовый код; модуль погашает его |
| Поиск | `frood-ledger`, `frood-api`, `frood-mcp` | Гибридный: Postgres FTS + pgvector (косинус), слияние RRF; без аккаунта эмбеддингов — только слова. `GET /v1/search`, MCP `search_knowledge` |
| Postgres | compose, CI, тесты | Образ с pgvector (`pgvector/pgvector:pg18-trixie`) |

## 3. Чьё это действие (R1′)

- Заметка, которую человек отправил сам (Telegram, Shortcut, AI-клиент), и всё, что `extract` из неё извлёк, — его: `user:<id>/via/<канал>`. Новые факты без конфликта принимает политика «свои факты».
- Из источников, которые захватил не человек (интеграции, ночной проход), `extract` предлагает как `agent:extract` — на ревью.

## 4. Отличия от плана MVP

| Что | Почему |
|---|---|
| Dispatcher и очередь запусков по событиям — в M3, а не в M4 | Без них `source.captured` не запускает распознавание и извлечение; в M4 добавятся расписания, агенты, вопросы |
| Связка аккаунта Telegram по коду — в M3, а не в M5 | Голосовое в Telegram должно быть чьим-то |
| Стандартные джобы встроены в ядро, а не импортируются бандлом из реестра | Реестра ещё нет; переопределение в `jobs:` работает так же |
| Файлы в Postgres (`blobs`), а не в модуле объектного хранилища | Голосовые маленькие; модуль `storage.objects` — когда понадобятся большие файлы |

## 5. Проверка

- Тесты с записанными ответами моделей и распознавания (моковые HTTP-серверы, P6): capture → transcribe → extract → предложение принято → поиск находит; русская заметка находится английским запросом (эмбеддинги в тесте детерминированные).
- Telegram-модуль против мокового Bot API.
- Вживую — на локальном Frood автора, когда будут ключи: бот Telegram (BotFather) и ключ OpenAI или Anthropic в `.frood/secrets.env`.

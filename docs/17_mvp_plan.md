# План реализации MVP, v0.1

> Статус: **принят 2026-10-18** (раунд 9). Лицензия ядра — AGPL-3.0 + CLA (L1). Репозиторий приватный до отмашки автора (открыт 24.10). Детализация по фазам 1–6 закончена; этот документ переводит принятые решения в порядок работ.
> Основание: все принятые решения (журнал в [README.md](README.md)), сквозной тест из 02 §13.3, 16 §14.

## 1. Критерий готовности MVP

Сценарий проходит целиком, автоматически (e2e-тест в CI) и вручную на VPS:

1. **Записать договорённость через один клиент:** голосовое в Telegram «Договорились с Олей: релиз 2.4 — 14 ноября».
2. **Прочитать через другой клиент:** в Claude (или ChatGPT Enterprise, или Claude Code) спросить «какие сроки в ноябре?» — ответ со ссылкой на утверждение и источник.
3. **Фоновый агент находит противоречие:** ночной проход по источнику (через MCP) находит «релиз переносим на 28.11» → конфликтное предложение → запись в Inbox → сообщение в Telegram с кнопками.
4. **Перезапуск сервера:** предложение и запись в Inbox на месте.
5. **Вердикт кнопкой** в Telegram → старая версия `superseded`, новая `active`; в любом клиенте видна история.
6. **Бэкап и восстановление:** бэкап в два хранилища, восстановление на чистой машине, сценарий читается заново.

## 2. Что входит и что нет

| Область | В MVP | Позже |
|---|---|---|
| Ядро | API (capture, утверждения, сущности, предложения, вердикты, Inbox, журнал, запуски, вопросы), Ledger, dispatcher, расписания, очередь, хост модулей, конфиг из файла и git, ревизии | push-источник конфига |
| Хранилище | Postgres (встроенный модуль) | другие провайдеры через экспорт / импорт |
| Вход | OAuth-сервер: CIMD + DCR, PKCE, refresh; вход через Google и любой OIDC (корпоративный SSO); личные токены | Apple, Microsoft, GitHub |
| MCP | Streamable HTTP без сессий + совместимость с 2025-11-25; инструменты: поиск, list_assertions, get_context (простой), capture_note, propose_change, list_inbox, get_proposal, submit_verdict, list_questions, answer_question | карточки MCP Apps, Tasks |
| Поиск | Postgres FTS + pgvector, многоязычные эмбеддинги через провайдера | графовая проекция |
| LLM | `llm.complete` через API-ключи Anthropic и OpenAI | CLI вендора без инструментов |
| Агенты | `agents.execute`: контейнеры на VPS с Claude Code (API-ключ или подписка) и Codex; ask_user, сообщения на ходу, продолжение сессии; аккаунты и бюджеты | Air, Managed Agents, OpenCode, ACP |
| Ввод | `/v1/capture`, Telegram (текст, голос, файлы), одно облачное распознавание речи | разбор документов, встречи, бот во встрече, локальный Whisper |
| Источники | `sources.mcp` (встроенный) с одним MCP-источником (Slack MCP или Glean) | pull- и push-коннекторы |
| Джобы | extract, daily-sweep, investigate, digest, напоминания по срокам | lifecycle-review, reverify, агент-настройщик |
| Внимание | Inbox, простые правила маршрутизации, лимиты, тихие часы, «исследовать перед обращением» для конфликтов | классификатор, эскалация |
| Каналы | Telegram: send / ask / update, кнопки ставят вердикт, связка аккаунта по коду | Slack, ntfy, web push, почта, OpenClaw / Hermes |
| Админ-панель | здоровье, запуски (повтор, отмена), события, логи, Inbox | расходы, ревизии с diff, Explorer, аудит |
| Платформа | `frood init / plan / apply / status / backup / restore / export`; деплой Docker Compose; бэкап restic в два S3-хранилища + проверка; снапшот перед обновлением | реестр с подписями, Helm, rollback-миграции сложнее expand / contract |

## 3. Этапы

Каждый этап заканчивается демонстрируемым результатом.

| Этап | Что делаем | Результат |
|---|---|---|
| **M0. Скелет** | Монорепозиторий, Rust workspace, CI, docker-compose для разработки, миграции Postgres, схема `frood.yaml`, `frood init / plan / apply` минимально | Пустая инсталляция поднимается одной командой |
| **M1. Ledger + API** | Source, Observation, Assertion (версии, три времени), Proposal / Verdict, журнал с outbox, политика «свои факты без конфликта принимаются» | Тесты: запросы по времени, атомарное применение, устаревшая база |
| **M2. Вход + MCP** | OAuth-сервер (CIMD, DCR, PKCE, refresh), вход через Google и OIDC, личные токены; MCP-адаптер и инструменты | Подключаются Claude (веб и телефон), ChatGPT Enterprise, Claude Code |
| **M3. Ввод и извлечение** | `/v1/capture`, Telegram-канал (ввод), облачное распознавание, `extract` с поиском похожих, связывание сущностей, поиск | Шаги 1–2 сценария |
| **M4. Задачи и агенты** | События, правила, dispatcher, расписания, очередь; запуски с ожиданием ответа; рантайм «контейнеры на VPS» (Claude Code, Codex); ask_user, сообщения на ходу; аккаунты, бюджеты; `daily-sweep` по MCP-источнику | Шаг 3 (без уведомления) |
| **M5. Inbox и уведомления** | Записи Inbox, маршрутизация, Telegram: уведомления с кнопками и обновление сообщений; «исследовать перед обращением»; сводка; напоминания по срокам | Шаги 3–5 |
| **M6. Эксплуатация** | Админ-панель (минимум), логи и метрики, детекторы «заглохло», бэкапы в два хранилища с проверкой, экспорт, снапшот перед обновлением | Шаг 6 |
| **M7. Приёмка** | Сценарий как e2e-тест в CI + прогон на настоящем VPS с настоящими клиентами | MVP готов |

## 4. Репозиторий

```
frood/
  core/                  # Rust workspace: один бинарник frood (сервер + CLI)
    crates/
      frood-ledger       # модель знаний, версии, предложения, журнал
      frood-api          # HTTP API (axum), OpenAPI
      frood-mcp          # MCP-адаптер (rmcp)
      frood-auth         # OAuth-сервер, федерация, токены
      frood-dispatch     # события, правила, расписания, очередь, запуски
      frood-modhost      # хост модулей, разрешение возможностей
      frood-config       # конфиг, секреты, ревизии
      frood-cli          # init / plan / apply / backup / export…
  contracts/             # OpenAPI / JSON Schema возможностей + тесты соответствия
  modules/               # официальные контейнерные модули: telegram, stt-*, runtime-docker, ui-admin
  bundles/standard/      # стандартные джобы и инструкции
  deploy/compose/        # шаблоны деплоя
  docs/                  # этот каталог
```

Реестр модулей — отдельный репозиторий (`frood-registry`). Лицензии: ядро — AGPL-3.0 + CLA (L1); `contracts/`, SDK и официальные модули — Apache-2.0, чтобы сторонние модули могли быть под любой лицензией.

## 5. Как тестируем

- **Контракты:** тесты соответствия для каждой возможности; модули прогоняют их в CI.
- **Ledger:** property-тесты на запросы по времени, атомарность, идемпотентность предложений, устаревшую базу.
- **LLM и агенты в CI:** записанные ответы провайдеров (record / replay), чтобы CI был детерминированным и бесплатным; отдельный ночной прогон с настоящими моделями.
- **e2e:** сценарий из §1 в docker-compose с фейковыми Telegram и MCP-источником.

## 6. Риски

| Риск | Что делаем |
|---|---|
| Клиенты отстают от спеки MCP или по-разному реализуют OAuth | Ранний этап M2 проверяется на настоящих клиентах; совместимость с 2025-11-25 |
| Условия подписок меняются (Anthropic, OpenAI) | Аккаунт с подпиской — опция; API-ключ всегда работает |
| Качество извлечения: «обсуждали» принимается за «договорились» | Политика: от агентов всё на ревью; evals на реальных примерах с M3 |
| Стоимость агентов | Бюджеты с M4; `llm.complete` там, где хватает одного вызова |
| Rust замедляет итерации | Ядро маленькое; ML-части — контейнерные модули на любом языке |

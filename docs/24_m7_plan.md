# M7. Приёмка — план реализации

> Этап M7 из [17_mvp_plan.md](17_mvp_plan.md): сценарий MVP целиком — автоматически (e2e-тест в CI) и вручную на VPS с настоящими клиентами. Результат — MVP готов.
> Основание: критерий готовности MVP (17 §1, шаги 1–6), фаза 6 ([16_platform.md](16_platform.md) §6: Docker Compose на VPS, Caddy для TLS), заметки о проверке с облачными клиентами ([18](18_implementation_log.md), M2).

## 1. Что строим

| Часть | Что |
|---|---|
| e2e-тест сценария | Один тест в CI на настоящем PostgreSQL проходит шаги 1–5 через настоящее ядро: голосовое через Telegram-модуль → распознавание → извлечение → ответ через MCP со ссылкой на утверждение и источник → ночной проход агента по источнику → конфликт → запись Inbox → сообщение с кнопками → перезапуск ядра → вердикт кнопкой → история в MCP. Внешние сервисы (Telegram, распознавание, модель, агент) — поддельные, ядро и база — настоящие (E1) |
| e2e шага 6 в CI | Docker-прогон: `frood init / apply` из исходников, модуль бэкапа с папкой и S3-совместимым хранилищем в контейнере, бэкап и проверка, удаление установки, `frood restore`, сверка экспорта до и после |
| HTTPS | Caddy сервисом в том же Compose, когда задан `server.public_url`: сертификат Let's Encrypt получает сам, наружу — только 80 и 443; база и модули — только внутри (E2) |
| VPS | Чистый Debian/Ubuntu с Docker; исходники — клоном по ключу только для чтения, образы собираются на месте; `frood init / apply`, вход через Google (E3) |
| Ручной прогон | Шаги 1–6 на VPS: голосовое в настоящем боте, вопрос в Claude (веб и телефон) и в Claude Code, ночной проход агента подпиской по источнику, кнопка в Telegram, бэкап в два хранилища, восстановление на другой машине, сценарий читается заново. Протокол — в docs/18 |

## 2. Проверка

- e2e-тест зелёный в CI на каждом коммите; шаг 6 — отдельной джобой CI с Docker.
- Ручной прогон по шагам 1–6 на VPS, с вашими клиентами; расходы на модели — по согласованию (QV4).

# M6. Эксплуатация — план реализации

> Этап M6 из [17_mvp_plan.md](17_mvp_plan.md): админ-панель (минимум), логи и метрики, детекторы «что-то заглохло», бэкапы в два хранилища с проверкой, экспорт, снапшот перед обновлением. Результат — шаг 6 сценария: бэкап в два хранилища, восстановление на чистой машине, сценарий читается заново.
> Основание: фаза 6 ([16_platform.md](16_platform.md) §6–10: снапшот перед обновлением, бэкапы restic в два хранилища с проверкой восстановления, переносимый экспорт, наблюдаемость), фаза 5 (N9′: веб — прежде всего админ-панель; детекторы создают тревоги в Inbox), D9″ (пользователи без ролей).

## 1. Что строим

| Часть | Где | Что |
|---|---|---|
| Админ-панель | ядро, `/admin` | Веб-страница поверх API (C1): здоровье (модули, отставание dispatcher, очередь, бюджеты, бэкапы), запуски с фильтрами — повторить, отменить, написать агенту, шаги запуска; лента журнала; последние логи ядра; Inbox. Вход — тем же входом, что у AI-клиентов |
| Логи и метрики | ядро | Структурированные логи уже есть; ядро держит последние строки своих логов для панели (C2); `GET /metrics` в формате Prometheus: отставание dispatcher, очередь, запуски и ошибки, расходы, возраст checkpoint источников, результаты бэкапов |
| Детекторы «заглохло» | ядро | Проверки раз в несколько минут создают тревоги в Inbox и сами их закрывают, когда всё наладилось: dispatcher отстаёт, запуск висит, джоба падает подряд, источник давно не читался, бюджет аккаунта на исходе, модуль не отвечает, бэкап старый или проверка не прошла (C3) |
| Бэкапы | модуль `backup-restic` + джоба `backup` | Дамп базы (в ней всё: знания, журнал, файлы, ревизии конфига, Inbox), `frood.yaml` и файл секретов, зашифрованный ключом восстановления, в несколько хранилищ restic; расписание и хранение — из конфига; проверка восстановления в отдельной базе рядом с рабочей (C4) |
| Восстановление | CLI | `frood restore --from <хранилище>` на чистой машине: база, конфиг, секреты (ключом восстановления), затем `frood apply` |
| Снапшот перед обновлением | CLI | `frood apply` перед новыми миграциями делает локальный дамп в `.frood/snapshots`, держит последние 5 (C5) |
| Экспорт | CLI | `frood export <папка>`: JSONL журнала, утверждения со всеми версиями, сущности, предложения и вердикты, источники и доказательства, файлы, `schema-version.json` и Markdown по сущностям — формат не зависит от СУБД |

## 2. Проверка

- Экспорт тестового сценария и сверка: каждое утверждение с историей, источники с цитатами, файлы.
- Бэкап в два локальных хранилища restic (диск + S3-совместимое в контейнере), проверка восстановления, `frood restore` в чистую инсталляцию → поиск находит то же, история та же.
- Детекторы: остановленный модуль, зависший запуск, просроченный бэкап → тревоги в Inbox и Telegram; восстановление закрывает их.
- Вживую — бэкап в ваши хранилища (вопрос QM6).

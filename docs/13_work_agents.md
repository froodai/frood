# Фаза 3. Фоновые задачи и агенты, v0.3

> Статус: **v0.2 одобрена 2026-10-17** (ответы в §15); v0.3 — правка W2″: режимы джоб стали возможностями модулей. v0.1 была отправлена на переделку (ответы в §12). v0.2 — переработка: всё, что запускает работу, — события; джобы, инструкции, рантаймы и аккаунты описываются в конфиге инсталляции; запуски интерактивные (вопросы, управление на ходу, продолжение); где и как запускать — забота реализации рантайма.
> Основание: D5, D6′, D7′, модель знаний v0.2, API v0.2.

## 1. Словарь

| Понятие | Что это | Пример |
|---|---|---|
| **Event** | Всё, что произошло: событие журнала Ledger, тик расписания, внешний вебхук, ручной запуск, ответ на вопрос агента | `source.captured`, `schedule.tick(daily-sweep)`, `question.answered` |
| **Rule** | Правило в конфиге: «на такие события запускать такую джобу с такими входами» | `on: proposal.verdict where verdict=investigate → run: investigate` |
| **Dispatcher** | Компонент платформы: читает поток событий со своим checkpoint, применяет правила, создаёт запуски | — |
| **Scheduler** | Источник событий по времени: по cron из конфига выпускает тики | `0 3 * * *` → `schedule.tick` |
| **Job** | Описание работы в конфиге: режим, инструкции, инструменты, скиллы, рантайм, аккаунт, права, бюджет, политики | `daily-sweep` |
| **Run** | Один запуск джобы: состояние, сессия рантайма, рабочая папка, журнал шагов, стоимость, результат | запуск #91 |
| **Question** | Вопрос агента человеку из запуска; ответ продолжает запуск | «Это решение или только обсуждение?» |
| **Runtime** | Реализация, которая исполняет агентов: контейнеры на VPS, JetBrains Air, Claude Managed Agents, OpenCode… | `air-cloud` |
| **Account** | Чем платится запуск: API-ключ, подписка пользователя, кредиты платформы | `anthropic-key`, `my-claude-max`, `jetbrains-ai` |

Исправление терминологии (по ревью W1): триггер — это событие, он ничего не читает. Читает поток событий **dispatcher**.

## 2. Как запускается работа

```
Ledger journal ─┐
Scheduler ticks ├─▶ event stream ─▶ Dispatcher (checkpoint) ─▶ rules ─▶ Runs ─▶ Runtime
Webhooks        │                                                  ▲          │
Manual / API    │                                                  │          ▼
Answers ────────┘                                       question.answered   Proposals, Questions, events
```

- Все источники событий сливаются в один поток; dispatcher читает его по порядку со своим checkpoint и после простоя догоняет.
- Scheduler выпускает тики по расписаниям из конфига; пропущенный тик выпускается один раз после старта. Дельту за весь пропущенный период джоба берёт по checkpoint источника.
- Доставка «хотя бы раз»: у запуска ключ идемпотентности, предложения тоже идемпотентны, повтор не плодит дублей.
- Сбой — повтор с растущей задержкой; после N попыток — список проблемных запусков и уведомление. Таймауты, отмена, бюджеты.

## 3. Всё — в конфиге инсталляции

(По ревью W3, W7, QW3, QW4.) Джобы, правила, инструкции, скиллы, рантаймы и аккаунты описываются в `frood.yaml`. Расписания, выбор рантайма, бюджеты — настройки конкретной инсталляции, не платформы.

```yaml
accounts:
  anthropic-key:  { kind: api_key, provider: anthropic, secret: ${secret:ANTHROPIC_KEY} }
  openai-key:     { kind: api_key, provider: openai,    secret: ${secret:OPENAI_KEY} }
  jetbrains-ai:   { kind: platform_credits, provider: jetbrains }

runtimes:
  local:     { impl: docker, agents: [claude-code, codex, opencode] }   # на этом VPS
  air-cloud: { impl: jetbrains-air, org: ${env:AIR_ORG} }

imports:
  - registry: frood/standard@1.2        # стандартный набор (W8), можно переопределять

jobs:
  daily-sweep:
    uses: agents.execute
    on:
      - schedule: "0 3 * * *"
        timezone: Europe/Amsterdam
        for_each: source
    instructions: ./agents/daily-sweep.md     # или inline: |
    skills: [./skills/meeting-vs-decision]   # формат Agent Skills
    tools: [frood, "source:${source}"]       # MCP-серверы
    runtime: air-cloud
    account: jetbrains-ai
    permissions: [knowledge:read, knowledge:capture, knowledge:propose]
    ask_user: { allowed: true, expire_after: 3d, on_expire: skip }
    auto_accept: { when: authoritative_source, no_conflict: true }
    budget: { max_usd: 0.50, max_minutes: 15 }

  extract:
    uses: llm.complete            # один вызов; agents.execute — одной строкой
    on: [{ event: source.captured }]
    account: anthropic-key
```

**Где лежит конфиг — выбирает пользователь** (тип модуля `config.source`):

| Вариант | Как меняется |
|---|---|
| Локальный файл на сервере | Правка файла + `frood apply` |
| Git-репозиторий | Платформа следит за веткой и применяет изменения; правки — через pull request |
| Push через API / вебхук | `POST /v1/config` с подписью; удобно для своих инструментов |

Платформа хранит **ревизии применённого конфига** с историей и откатом; изменение конфига — тоже событие.

## 4. Джоба вызывает возможность модуля

(По ревью W2 → W2″: «почему llm и agent не подтип service из extension?» — так и сделано.) У ядра нет списка режимов. Джоба указывает, какую возможность (capability) вызвать, и передаёт входы; возможность даёт установленный модуль.

| Возможность | Кто даёт | Пример джобы |
|---|---|---|
| `agents.execute@v1` | модуль рантайма: контейнеры на VPS, JetBrains Air, Managed Agents… | `daily-sweep` |
| `llm.complete@v1` | модуль LLM gateway: API-ключ или CLI вендора без инструментов | `extract`, `digest` |
| `media.transcribe@v1` | модуль распознавания речи | `transcribe` |
| `docs.parse@v1` | модуль парсинга документов | `parse` |
| любая другая | любой установленный модуль | — |

```yaml
jobs:
  extract:
    uses: llm.complete          # agents.execute — одной строкой
    with: { account: anthropic-key, instructions: ./extract.md }
```

- Новый вид работы появляется установкой модуля, ядро не меняется.
- **Стоимость:** агент делает несколько вызовов модели и на каждом шаге заново отправляет инструкции, описания инструментов и накопленный контекст, поэтому на простой задаче он обычно в разы дороже одного вызова. Выбор между `llm.complete` и `agents.execute` — вопрос цены, а не архитектуры.
- В стандартном наборе `extract` идёт через `llm.complete`: платформа перед вызовом подставляет похожие существующие утверждения, чтобы модель увидела возможные конфликты.
- Если есть только подписки, `llm.complete` может работать через CLI вендора без инструментов (например, `claude -p`) ⚠️ (§8).

## 5. Интерактивные запуски

(По ревью W4, W5, W6: у агента бывают вопросы, сессию надо продолжать, песочницу — возрождать, агентом — управлять на ходу.)

### Состояния запуска

```
queued ─▶ running ─▶ succeeded / failed / cancelled
             │  ▲
   ask_user  ▼  │ answer / steering message
        waiting_for_input ──(истёк срок)──▶ on_expire: skip | cancel | default_answer
```

### Вопрос агента

1. Агент вызывает инструмент `ask_user(question, options?, context?)` из MCP Frood (доступен только токену запуска).
2. Создаётся **Question**; он попадает в Inbox и в каналы уведомлений (фаза 5); запуск переходит в `waiting_for_input`, процесс рантайма может завершиться.
3. Пользователь отвечает в Inbox, мессенджере или чате (`answer_question` в MCP) → событие `question.answered`.
4. Dispatcher продолжает запуск: **та же сессия** (resume по id сессии), если рантайм умеет; иначе **новый запуск** с кратким итогом прошлого и парой вопрос-ответ в контексте.
5. Если в ответе есть новое знание, он сохраняется как источник (ваша заметка) и проходит обычное извлечение.

### Управление на ходу

- `POST /v1/runs/{id}/messages` — сообщение запущенному или ожидающему агенту: «сфокусируйся на X», «не трогай Y», «вот ещё ссылка».
- Если рантайм принимает ввод на ходу, сообщение доставляется сразу; иначе ставится в очередь и уходит при продолжении.
- Отмена текущего шага и полная остановка — отдельные операции.

### Рабочее окружение

- У запуска есть рабочая папка (файлы, заметки агента). Она сохраняется между шагами, чтобы окружение можно было восстановить при продолжении.
- Где хранится — решает реализация рантайма: том или объектное хранилище для контейнеров на VPS; у Air результат пушится в ветку после каждого хода; у Managed Agents состояние песочницы хранится на стороне сервиса.

## 6. Что агент может делать с памятью

- Писать через MCP Frood токеном запуска: `read`, `capture`, `propose`, плюс `ask_user` и `report_progress`.
- **Вердикт по достоверным источникам** (по ревью W4) — через политику: в джобе `auto_accept: { when: authoritative_source, no_conflict: true }`. Агент предлагает с доказательством, а политика сама принимает, если источник помечен в конфиге как достоверный и конфликта нет. В аудите видно: «принято политикой джобы daily-sweep». Самого права `decide` у агента нет.
- Результат запуска: отчёт + id предложений и вопросов; каждое предложение ссылается на запуск, джобу и ревизию конфига.

## 7. Контракт рантайма `agents.execute@v1`

| Операция | Смысл |
|---|---|
| `capabilities()` | Что умеет реализация: ввод на ходу, продолжение сессии, MCP, скиллы, сохранение окружения, контроль сети, модели, где запускает |
| `start(spec) → run` | spec: инструкции, скиллы (файлы), MCP-серверы (адреса + ссылки на секреты), модель, аккаунт, токен запуска, бюджет, рабочая папка |
| `send(run, message)` | Сообщение агенту: управление на ходу или ответ на вопрос |
| `resume(run, session_ref, message?)` | Продолжить сохранённую сессию |
| `cancel_turn(run)` / `stop(run)` | Прервать текущий шаг / остановить запуск |
| `status(run)` / `events(run)` | Состояние; поток шагов, вызовов инструментов, токенов, стоимости |

**Изоляция и место запуска — ответственность реализации.** Контракт требует только: передавать агенту лишь токен запуска и объявленные секреты; честно объявлять в `capabilities()`, что умеет (продолжение, сеть, сохранение окружения) и где запускает.

### Реализации

| Реализация | Где | Ввод на ходу | Продолжение | MCP и скиллы | Заметки |
|---|---|---|---|---|---|
| Docker на VPS + Claude Code | этот сервер | да (streaming input в Agent SDK) ✅ | да, по id сессии ⚠️ | да | Изоляцию и сеть задаём сами |
| Docker на VPS + Codex | этот сервер | не документировано для `codex exec` ⚠️ | да: `codex exec resume <id>` ✅ | MCP да | |

| ACP-агенты | где угодно | `session/prompt`, `session/cancel` | `session/load` | зависит от агента | Общий протокол |

## 8. Аккаунты и подписки

(По ревью QW1: начать с Anthropic, OpenAI, JetBrains; что с подписками.)

| Аккаунт | Тип | Для каких режимов | Ограничения |
|---|---|---|---|
| Anthropic API-ключ | `api_key` | все | оплата по использованию |
| Подписка Claude Pro / Max | `subscription` | агент через Claude Code CLI (`claude setup-token`) | С 15.06.2026 фоновое использование (`claude -p`, Agent SDK, GitHub Actions) идёт из отдельного месячного лимита: ~$20 Pro, $100 / $200 Max ⚠️. Agent SDK, по сторонним данным, требует API-ключ ⚠️. Нельзя пускать через свою подписку запросы других людей ⚠️ |
| OpenAI API-ключ | `api_key` | все | оплата по использованию |
| Подписка ChatGPT | `subscription` | агент через Codex CLI со входом через ChatGPT (`codex login --device-auth` без браузера ⚠️) | лимиты плана ⚠️ |
| JetBrains AI | `platform_credits` | агенты в Air | Облачные задачи и автоматизации тратят кредиты подписки JetBrains AI; свои ключи — только для локальных задач ✅ |

Правила:
- API-ключ принадлежит инсталляции; подписка — конкретному пользователю и используется **только для запусков от его имени**.
- Джоба выбирает аккаунт в конфиге; можно задать запасной.
- Бюджеты на джобу и на аккаунт; значения по умолчанию консервативные, траты видны в Activity (по QW2 ориентира нет).

## 9. Развитие инструкций

(По ревью W7.) Инструкции — часть конфига, поэтому меняются тем же путём, что и конфиг:
- если конфиг в git — pull request;
- если файл или push через API — **предложение изменения конфига** в Inbox (diff), после принятия платформа применяет его в источник конфига.

Причины отклонённых предложений копятся как обратная связь к джобе. Агент-настройщик (позже) по ним предлагает правки инструкций тем же путём. Примеры для проверки (evals) прогоняются перед применением.

## 10. Стандартный набор v1 (W8, принято)

Поставляется как импортируемый бандл `frood/standard`; каждую джобу можно переопределить в конфиге.

| Джоба | Возможность | Событие | Делает |
|---|---|---|---|
| `transcribe` | media.transcribe | `source.captured` (аудио) | Распознавание речи |
| `extract` | llm.complete | `source.captured` (текст) / после `transcribe` | Observations → Proposals |
| `daily-sweep` | agents.execute | тик расписания, по источнику | Новое, изменения, конфликты |
| `investigate` | agents.execute | вердикт `investigate` | Дособрать контекст, дополнить Proposal |
| `lifecycle-review` | agents.execute | утверждение-событие о merge / закрытии | Поштучно: в историю или оставить |
| `reverify` | agents.execute | `review.due` | Проверить актуальность |
| `digest` | llm.complete | тик расписания | Утренняя сводка |

- **JetBrains Air:** облачные агенты в контейнерах; автоматизации по расписанию и событиям работают в облаке без вашей машины; облачные задачи тратят кредиты JetBrains AI, свои ключи — только локально; результат пушится в ветку после каждого хода; приостановленную задачу можно продолжить до архивации через 24 ч ✅ [Air: Cloud agents](https://www.jetbrains.com/help/air/cloud-agents.html). Поддерживаемые агенты: Claude Agent, Codex, Gemini CLI, Junie ✅ [Supported agents](https://www.jetbrains.com/help/air/supported-agents.html). Air CLI: `aircli cloud run` (агент, модель, окружение, системный промпт, переменные), `status`, `cancel`; `aircli remote prompt / resolve / cancel / stop` для сессий на машине; сейчас работают только echo-сессии ✅ (локальный skill aircli). MCP в облачных задачах в документации не упомянут ⚠️.
- **Подписка Claude:** `claude setup-token` даёт долгоживущий токен для headless; с 15.06.2026 программное использование идёт из отдельного лимита; Agent SDK требует API-ключ; запрещено пускать чужие запросы через свою подписку ⚠️ (сторонние источники: [гайд по ToS](https://autonomee.ai/blog/claude-code-terms-of-service-explained/), [кредиты Agent SDK](https://techsy.io/en/blog/claude-agent-sdk-credit)). Проверить по официальным документам Anthropic перед реализацией.
- **Codex:** `codex exec resume --last | <SESSION_ID>` сохраняет транскрипт и историю ✅ [Codex CLI features](https://developers.openai.com/codex/cli/features); вход через ChatGPT, `codex login --device-auth` для headless ⚠️; app-server с WebSocket ✅.
- **Claude Agent SDK:** streaming input — долгий процесс с прерываниями и очередью сообщений; `interrupt()` ✅ [Streaming vs single mode](https://code.claude.com/docs/en/agent-sdk/streaming-vs-single-mode); продолжение по id сессии ⚠️.

### OpenCode и биллинг

- OpenCode — open source, сам по себе бесплатный; работает с вашими ключами провайдеров или локальными моделями.
- Платные опции у команды OpenCode есть, но не обязательны: OpenCode Zen (шлюз к моделям с оплатой по запросам) и OpenCode Go (подписка ~$10/мес) ⚠️.
- **Подписку Claude в OpenCode использовать нельзя:** с апреля 2026 Anthropic запретил расходовать лимиты подписки через сторонние инструменты (OpenCode, OpenClaw и т.п.); только через Claude Code ⚠️. Вход через подписку ChatGPT в OpenCode упоминается, но разрешено ли это OpenAI — не подтверждено ⚠️.
- Вывод: для подписок Claude используем Claude Code, для подписок ChatGPT — Codex; OpenCode — для API-ключей и локальных моделей.
